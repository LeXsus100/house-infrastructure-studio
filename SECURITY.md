# Security policy

## Supported version

Security fixes are applied to the latest release and the current `main` branch.

## Reporting a vulnerability

Do not publish a vulnerability, private floor plan, project backup, database, blueprint, photograph, credential, or signing key in a public issue.

Use the repository's **Security → Report a vulnerability** form (GitHub private vulnerability reporting). Include the affected version, local reproduction steps, impact, and the smallest non-private test project that demonstrates the issue. If private vulnerability reporting is not enabled, ask the repository owner for a private reporting channel without including sensitive details.

The application intentionally has no cloud service, authentication system, telemetry, or public network listener. Reports about a deployment or public listener are out of scope unless the repository itself introduced that behavior.
